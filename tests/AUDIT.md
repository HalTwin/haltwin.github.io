# Yield Terminal 「一键操作」— 说明(聚合跳转版)

被审对象:`terminal.html`(374 行)。`⚡` 那个按钮从"禁用的 SOON"变成一个
**跳到第三方交互页的链接**。

## 这一版是什么

和国库页面完全同一套做法:**只做聚合跳转**。

- 命中白名单的路由 → 一个 `<a target="_blank" rel="noopener noreferrer">`,
  指向**人工核对过的**第三方落地页(目前:X Layer USD₮0 aave-v3 →
  OKX earn 产品页 33905,和国库页 `aUSD₮0` 走的是同一个 URL)。
- 用户在**第三方站上**审阅、连钱包、签授权。**Sterling 不代签、不碰用户的钱、
  calldata 一个字节都不经手。**
- 其余路由禁用,并各自写明原因(不用笼统的 SOON)。

## 为什么这版几乎没有安全面

前一版(代签)要在我们站上构造并发起交易,于是有一长串只有代签才会有的风险:
双花、授权残留、回执核验、防重发。**跳转版这些全部不存在** —— 因为交易根本
不在我们这边发起。安全面和国库页一模一样,而国库页早就在线上。

## 唯一保留的铁律

**落地 URL 是白名单表(`DEST`)里的常量,绝不从 DefiLlama 的行情字段拼出来。**

否则被污染的行情能把用户导到"用 USD₮0 换一个假币"的页面。匹配沿用严格三段:

- `chain` 严格相等 —— USD₮0 在 Mantle / X Layer 同地址,只看 project+token
  会让 Mantle 的卡片亮着却跳到 X Layer 的 earn 页(点的和落地的不一致)。
- `underlyingTokens` 恰好一个元素 —— 多元素是 LP / 套娃池,跳单币 earn 页是错的。
- `project` 在表里。

命中后,URL、币名全部取自表;行情只用来"查表决定亮不亮"。另加一道
`^https://` 白名单,表被改坏也不会渲染出 `javascript:` 链接。

## 复跑

```bash
node tests/test-redirect.mjs    # 28 项:匹配门 + "URL 来自表不来自行情"这条铁律
```

变异验证(建议自己也跑):去掉 chain 匹配 / 放宽数组长度 / go_url 改用行情拼 /
去掉 https 校验 / 按钮文案改用行情 symbol —— 五个破坏都能被测出来。

## 局限

- 跳错页的风险仍在(但用户在第三方站上会看清自己在操作什么),不再是"钱打进错地址"。
- 第三方页面本身、钓鱼仿冒第三方、我们站被替换 —— 这些前端都消不掉,和任何带外链的页面一样。
- 目前只有一条路由有核对过的落地页;要扩就往 `DEST` 表里加,每加一条都要人工核对 URL。

此前有一版把「一键操作」做成"在 Sterling 站上直接签存款交易",经 Codex / Grok
八轮审计。**需求澄清后该方案整个废弃** —— 产品定位是聚合跳转,不代签。

比把复杂形态做对更重要。
